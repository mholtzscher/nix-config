# Standalone Mise

Mise itself is installed outside Nix on every machine, at `~/.local/bin/mise`. Its Nix module, host settings, flake input, and lockfile dependencies are removed. Shared live configuration enables native `[settings.self_update] auto = true`; no custom updater is needed. The `usage` completion helper is a normal Mise-managed tool.

Shell activation and completion setup live in native tracked sources under `~/.config/mise/dotfiles/shell/`, deployed as `~/.config/shell/` snippets. Nix only has generic includes for those snippets in the shells it still manages; it neither generates Mise activation nor owns Mise settings. Mac startup files source the same snippets directly.

## Handoff

Keep the current terminal open. Install the official executable **before** applying the Nix changes that remove its old package.

On either Mac or Ubuntu:

```sh
curl -fsSL https://mise.run | sh
~/.local/bin/mise --version
```

On NixOS, select the static build so Mise itself does not need a system dynamic linker:

```sh
curl -fsSL https://mise.run | MISE_INSTALL_MUSL=1 sh
~/.local/bin/mise --version
```

Confirm `2026.10.6` or newer. Do not use the shell-specific installer endpoints: activation is already configured. Existing Mise tools, dotfiles, credentials, caches, and history are reused; do not run `mise implode`.

Fetch the shared setup and regenerate activation/completions with the standalone executable:

```sh
~/.local/bin/mise dot sync
~/.local/bin/mise dot pull
~/.local/bin/mise bootstrap
~/.local/bin/mise bootstrap services apply
```

The services apply rewrites the history watcher and tool updater to use the permanent standalone executable, rather than a Nix store path. Stop for any dotfile or app adoption conflict instead of forcing it. New machines use the adoption steps in [Mac setup](mac-setup.md) or their existing enrollment procedure first.

Once these Nix changes are published, fetch, build, and apply the configuration with the normal host-specific Nix commands. **Only the user runs Nix apply commands.** Installing the standalone binary alone does not remove the package from the active Nix generation.

After bootstrap and the Nix switch succeed, open a fresh shell. Check:

```sh
command -v mise
mise --version
mise doctor
mise bootstrap services status
```

`command -v mise` should point to `~/.local/bin/mise`. Existing shells can retain old activation hooks or command caches until restarted. Nushell's startup snippet uses the local `~/.config/mise/activate.nu` generated by bootstrap; that generated file is not tracked or built in a Nix sandbox. NixOS still retains `nix-ld` for other precompiled tools. Its `all_compile = false` preference now lives in the shared writable Mise config, not a Nix fragment.

## Updates

Native automatic self-update checks before eligible interactive commands, subject to Mise's release-age policy; it does not update in every background invocation. To update manually:

```sh
~/.local/bin/mise self-update
```

`mise upgrade` updates managed tools, not Mise itself. Re-run bootstrap after setup changes; after a self-update, it also refreshes generated completions and shell activation. Restart shells to load the refreshed activation.
